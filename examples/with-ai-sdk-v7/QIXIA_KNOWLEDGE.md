## 三、导入内容

从知识库为每个景点导入了以下数据（结构见 `lib/qixia-knowledge/types.ts`）：

- **summary（简介）**：卡片概况
- **history（历史来历）**：机器整理的「来历」讲解词正文
- **historySources（出处）**：正文每句对应的来源链接列表
- **keyFacts（关键史实）**：按字段去重后的事实（始建年代、形制、文物保护级别、高度、位置等），同一字段保留多个来源说法
- **timeline（大事记）**：年代 + 事件
- **audio（讲解音频）**：喜马拉雅等平台的讲解/播客链接（标题、平台、作者、时长、播放量）
- **images（图片）**：维基共享资源开放许可图片（URL、标题、作者、许可、出处）

**数据统计（17 个景点合计）：**

| 项目 | 数量 |
|---|---|
| 关键史实字段（去重后） | 178 个 |
| 原始史实条数（含多来源） | 452 条 |
| 大事记 | 157 条 |
| 讲解音频 | 21 条 |
| 图片 | 46 张 |
| 含历史「来历」讲解的景点 | 14 个 |

这一层是**素材**：同一字段的多来源说法全部保留（如舍利塔高度 15 米 / 18.74 米）。对话回答和卡片正文不直接用它，而是用第五节描述的审核口径；素材只出现在卡片底部默认收起的「资料原文」里。

## 四、代码改动清单

### 新增文件

1. **`lib/qixia-knowledge/`**（按景点拆分的知识模块，分「素材」与「定稿」两层）
   - `types.ts` — 类型定义（`QixiaPlaceKnowledge`、`QixiaAnswerView` 等）
   - `data/<code>.ts` — 每个景点一个文件（如 `B5.ts` 为栖霞古寺），各自导出 `place<code>` 常量，多来源并列保留
   - `catalog.ts` — 聚合所有景点并导出 `getQixiaKnowledgeByCode`、`getQixiaKnowledgeByName`、`searchQixiaKnowledge`
   - `editorial.ts` — **审核层**：一句话简介、已拍板的要点（附 `basis` 依据）、大事记、待拍板项目名（`open`）、只供检索的名称（`searchOnly`）
   - `answer-view.ts` — 发布口径：只读 `editorial.ts`，没有审核条目的景点只用不带推测口吻的简介；`lookupQixiaKnowledge` 负责按景点名、编号、人物查询
   - `index.ts` — 统一出口（`catalog` + `answer-view` + 类型）
   - **扩充方式**：在 `data/` 下新增 `<code>.ts`（导出 `place<code>`），在 `catalog.ts` 的 import 与 `qixiaKnowledge` 数组各登记一行；需要对外发布要点时在 `editorial.ts` 补一条。

2. **`components/map/place-knowledge.tsx`**
   地点详情面板里的「景点知识」组件，展示简介、历史来历、大事记（可展开）、讲解音频、图片（带许可署名）。
   - 详情面板内为**精简预览**，含「查看完整知识卡片」按钮；简介与对话用同一份审核口径。
   - 全屏知识卡片的正文展示发布口径：简介、关键信息、大事记，以及讲解音频、图库（含作者与许可署名）。古籍另以默认折叠的「古籍记载」展示，标明历史记载不等同于现状；各来源的原始说法和出处收在底部默认收起的「资料原文」里；开放时间与票价采用独立的2026参考规则（`visitor-info.ts`），带确认日期和适用截止日期。
   - 卡片采用**红枫主题**：外层全屏背景为**枫叶红渐变**（深红 → 枫红 → 暖橙），四角有大枫叶装饰、背景中十余片金色/暖橙枫叶轻盈漂浮；卡片本体为**白色实底**（金色顶饰条 + 红枫渐变头部），在红底上清晰突出。
   - 支持 Esc 键、点遮罩、点关闭按钮三种方式退出；选中景点后若有资料会**自动弹出**卡片（无需再点小按钮）。

6. **`lib/place-context.ts`** — 地图选点的隐藏上下文：从消息 `metadata.custom.qixiaPlace` 读取名称、编号、地址、坐标，注入成一段说明，并让模型用编号查资料；字段不全就不注入，编号格式不对就丢弃

7. **`lib/qixia-chat-prompt.ts`** — 回答口径文案：`QIXIA_KNOWLEDGE_RULE`、`QIXIA_ANSWER_STYLE`、`formatPlaceContext`

## 五、对话口径与审核层

知识库导入的是**素材**：同一字段常有多个来源、多个数字（例如舍利塔高度同时有 15 米、18.04 米和 18.74 米）。素材不能直接给游客看，也不能交给程序按来源等级自动挑一个：等级字母本身就不可靠，自动挑选还会把「约」「相传」这类限定词丢掉。

对话和卡片共用 `answer-view.ts`：要点、大事记采用 `editorial.ts` 确认口径，未补充条目依用户要求暂沿用现有简介。

- **简介**：有审核条目用 `intro`；没有的用条目自己的 summary，但模板句和带「一说」「疑为」「或与」「误写」「待核」口吻的简介不用。
- **要点和大事记**：只有 `editorial.ts` 已确认的 `facts`、`timeline` 才发布；`status: "pending"` 的要点和事件会被过滤，待核实要点名进入 `unsettled`，素材字段不再自动进入回答。
- **没拍板的项目**：写进 `open`，只发布项目名（如「高度」）。模型被问到时只说「各资料说法不一，暂时没有定论」，不给候选值。候选值和出处见 `QIXIA_KNOWLEDGE_CONFLICTS.md`。
- **时效信息**：景区、入口与古寺条目通过 `visitorInfo` 提供独立的2026参考规则，确认于2026-10-30，参考截止2026-12-31。与历史facts分开，不宣称实时查询；模型超过截止日不能继续引用旧时段票价，临时安排以现场公告为准。
- **名称**：误写、相邻景点名写进 `searchOnly`，仍能搜到，但不作为「又名」展示。
- **来源写法**：介绍景点时正文不出现网址与 A/B/C，结尾固定一行「资料：栖霞知识库」；具体出处在卡片的「资料原文」里。

维护时：拍板的结论写进 `facts` 或 `timeline`，依据写进 `basis`；判断不了就写进 `open`。`answer-view.test.ts` 检查发布口径里没有网址、可信度、钟点和价格，冲突值不会被自动选中，地图上每个有卡片的点按名字都能查到自己的卡片。

地图选点进入对话同理：气泡里只说「介绍一下哼哈殿」，编号、坐标、POI 与「不代表当前位置」放在消息 `metadata.custom.qixiaPlace` 里，由 `injectPlaceContext` 在服务端补成模型上下文。

## 六、图片与许可说明

- 图片来自**维基共享资源（Wikimedia Commons）**开放许可，由栖霞知识库镜像存储，国内访问更快。
- 每张图均保留 `author`（作者）、`license`（许可）、`license_url`、`source`（原图页）。
- 许可类型：Public domain（公有领域）、CC BY / CC BY-SA（需署名，BY-SA 改编后须用同样许可）。
- **转用时务必按许可署名**，组件和图库中已展示作者与许可信息。
- 另：知识库还有「游客参考图」（小红书/B 站，版权归原作者，仅内部参考），因需登录且不可公开，本次**未导入**。

## 八、待办与注意事项

1. **7 个无独立卡片的景点**（牌坊、话山亭、枫林湖、太虚亭、半馆、百草园、饮马池）：知识库没有对应卡片。若要补齐，需从方志/景区资料另行整理，或在知识库补充卡片后再重新导入。
2. **数据时效与可信度**：知识库内容多为机器整理草稿（`status=draft`），可信度以 C 级为主。素材层仍保留全部说法，对外只走 `editorial.ts` 的审核结论；新增结论先核对出处；未确认的值标注 `status: "pending"`，不能直接发布，项目名写进 `open`。待拍板事项见 `QIXIA_KNOWLEDGE_CONFLICTS.md`。
3. **内部数据未接入**：商户/住宿名单需在 https://qixia.winnielyu.com/internal/ 邮箱登录后生成口令（`qx_...`）才能取，本次未导入。
4. **重新导入**：知识库更新后，可重跑生成脚本 `F:/fks-gihub/.workbuddy/tools/generate-qixia-knowledge.js` 覆盖 `lib/qixia-knowledge/` 下的数据文件（脚本内需把临时数据路径改为本机实际路径，并按上述拆分结构输出）。重跑只覆盖 `data/`，`editorial.ts` 里的定稿结论要人工复核：数据变了，拍板的话也要跟着改。
5. **数据体积**：知识数据约 200KB，随前端一起打包；如需进一步优化体积，可改为运行时按需请求知识库 API。
