# 定位推荐与原生道路

## 地图与点位

赏秋模式保留不透明黄色底（#f4f2af）、景点贴图、山体与湖泊装饰，直接显示高德 JS API 原生道路和建筑。透明前景地图负责道路、节点和交互；黄色地理 SVG 位于其下，同步的高德背景保留园外颜色和湖泊水面。背景地图必须允许程序缩放，鼠标事件由宿主禁用；切换底图、拖动和缩放保持两层中心与级别同步。原先的 qixia-roads.json 是步行规划轨迹子集，不能充当完整原生路网，已停止绘制其白色覆盖线。高德细路按自身规则在较高缩放级别展开，16 级起可见更多细节。

普通景点未展开时为小淡红点，贴图与名称展开后恢复正常红点；A/B/C 路线站点保留编号，选中点优先显示。

## 定位和推荐

浏览器位置经高德从 WGS-84 转为 GCJ-02。每次发消息读取最新位置、精度、时间和 A/B/C 路线；位置仅驻留内存。超过 30 秒、误差超过 50 米或关闭定位时，不作为当前起点；缺失定位时请游客说明所在地点。地图选中点不冒充游客当前位置。

recommend_qixia_trip 接受孩子年龄、推车、体力、兴趣、游览时间、已游景点、日期和返程地点。亲子关键信息缺失时先澄清；根据当前起点、目标路线和兴趣筛选节点，查询真实步行分段，加入停留、慢行、返程与 15 分钟机动预算。推车或低体力方案排除已知登高候选，跳过步行指令明确含台阶的路段及返程；没有台阶提示不等于已验证无台阶。

厕所、休息、餐饮、补给、返程需求优先单独处理；直线距离与步行距离分开，估算点不提供精确步行导航。每段保留自身的休息、厕所与返程起终点，天气查询使用用户所选游览日期。

高德步行调用串行间隔至少 420 毫秒，遇 QPS 或 HTTP 429 限流重试一次，成功结果缓存 10 分钟；失败结果不缓存。一段失败继续检查其他候选，不将网络失败当作道路不存在。缓存仅保存已完成的成功结果，避免某个请求取消后污染其他请求。

真实模型仍可能改写数字或添加没有依据的路况，因此已验证的路线和实用推荐正文由服务端根据工具数据组织，包含精确预算、分段、附近设施、来源、对应日期天气和已查询的短程返程。最终回复流保留工具状态，显示这份正文，避免模型再次计算。独立文化问题继续通过知识库工具回答；路线中的文化摘要也只采用知识库发布内容。介绍未收录的景点时不补写历史。

定位变化后，在下一次提问时重新规划；不会因 GPS 每次更新主动发送新消息。蓝色目的地导航仍由地图选择地点触发，不宣称实现了持续语音导航或自动偏航重算。

## 验证和边界

本地实际浏览器验证：桌面 14/16/18 级道路展开、手机黄色/高德切换、前后地图同中心同缩放、红点展开样式均正常，无捕获到的 JS 异常。手机模拟 GPS 经转换后连同当前 B 路线进入真实聊天请求。

真实模型端到端样本覆盖亲子推车、低体力、短时游、文化、餐饮、厕所、缺失定位与景点数字。最终版本再次核对亲子 105 分钟、短时 79 分钟和餐饮 95 米/2 分钟及返程 502 米/7 分钟；这些是当时起点和高德结果的样本，不是固定产品文案。舍利塔高度实际查询知识库后回答 18.04 米。

应用检查命令（从 examples/with-ai-sdk-v7 执行）：

```sh
node ../../node_modules/vitest/vitest.mjs run --exclude scripts/model-env.test.mjs
node --test scripts/model-env.test.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

验证结果：147 项 Vitest 测试、3 项 Node 测试和类型检查通过。Node 测试使用自身 runner，不交给 Vitest 收集。旧全景测试已按固定基础范围更新，避免把新增的外围 POI 错当作全景边界。

手机 GPS 为浏览器模拟验证，未现场测试设备定位；90 个估算点仍不具备导航精度保证。台阶、坡度、推车通行、店铺座位和实时营业未现场核验，当前路线不是认证无障碍路线。样本通过不代表任意模型输入都已验证。
